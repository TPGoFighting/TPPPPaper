# 前后端问题修复清单 — 2026-07-09 21:42

## 背景

TPaper 项目在公网部署后发现前后端集成和数据层问题。本文档列出所有待修复项，并按优先级逐项解决。

---

## P0 — 必须修复

### P0-1: 退出登录未清除会话
- **文件**: `web/src/components/Navbar.tsx:142-143`
- **问题**: 退出按钮是 `<Link href="/login">`，未调用 logout API，未清除 cookie
- **修复**: 改为 button，调用 `POST /api/auth/logout`，清除 session

### P0-2: 删除论文 Internal Error
- **文件**: `backend/app/api/papers.py:67-71`
- **问题**: `DELETE /api/papers/{id}` 手动级联删除，部分返回 Internal Server Error
- **修复**: 检查并修复 cascade 删除逻辑，添加异常处理

---

## P1 — 建议修复

### P1-1: 统一认证机制，移除死代码
- **文件**: `web/src/lib/api.ts:117-119`, `web/src/app/login/page.tsx:26`
- **问题**: `getToken()` 从 localStorage 读取 token 但从未写入，Bearer token 路径是死代码
- **修复**: 移除 localStorage token 逻辑，仅依赖 httpOnly cookie

### P1-2: 公开页面使用 API 客户端
- **文件**: `web/src/app/p/[slug]/page.tsx`
- **问题**: 使用原生 `fetch('/api/public/papers/...')` 而非 `api` 客户端
- **修复**: 改用 `api.get()`，统一错误处理

### P1-3: 添加全局 Error Boundary
- **文件**: `web/src/app/layout.tsx`
- **问题**: 无全局错误边界，页面白屏无提示
- **修复**: 添加 ErrorBoundary 组件

---

## P2 — 架构优化

### P2-1: 引入 Repository 层
- **问题**: API handler 直接执行 SQLAlchemy 查询，无抽象
- **修复**: 创建 `backend/app/repositories/` 目录，抽取数据访问逻辑

### P2-2: 使用 SQLAlchemy cascade
- **文件**: `backend/app/models/__init__.py`
- **问题**: 手动级联删除，未定义 cascade
- **修复**: 在关系上添加 `cascade="all, delete-orphan"`

### P2-3: 添加分页
- **文件**: `backend/app/api/papers.py`
- **问题**: `GET /api/papers` 返回全部记录
- **修复**: 添加 `page`/`size` 查询参数

### P2-4: 添加全局错误处理和重试
- **文件**: `web/src/lib/api.ts`
- **问题**: 无重试逻辑，错误处理分散
- **修复**: 在 API 客户端添加重试和统一错误处理
